I added a `bootstrap/` configuration for the S3 bucket, pointed the root backend at it, and rewrote the README for the new workflow. I haven't applied anything or migrated your state. Both configurations pass `terraform fmt -check` and `terraform validate`, but `tflint` isn't installed here, so it didn't run. I also didn't run a backend-enabled `init` or `plan`, since I have no AWS credentials.

**What changed**
- **`bootstrap/`** creates the bucket with versioning, KMS encryption at rest, public access fully blocked, a policy that denies non-TLS access, and `prevent_destroy`. Old state versions expire after 90 days. Its own state stays local, which the README explains.
- **`backend.tf`** points the root configuration at the bucket with `encrypt = true` and S3 native locking (`use_lockfile`). That needs Terraform 1.10 or later, which `versions.tf` already requires, so no DynamoDB table is needed.
- **`.gitignore`** is new and excludes state, plan files, `.terraform/` and `*.tfvars`.
- **`README.md`** now covers the one-time bootstrap, the `init -migrate-state` step, the plan-then-apply routine, stale-lock recovery and rolling back state.
- **`.terraform.lock.hcl`** is new, generated by `init`. It records checksums only for this machine's platform. If teammates or CI run on a different OS or architecture, run `terraform providers lock` for those platforms and commit the result. `bootstrap/` has its own lock file too.

**Things to know**
- **Bucket name placeholder:** `backend.tf` uses `reports-tfstate-example`. Bucket names are global, so change it to a unique name and pass the same value to bootstrap as `state_bucket_name`.
- **Secret key in state:** the existing `aws_iam_access_key.uploader` writes its secret key into state in cleartext. `sensitive` only hides it from CLI output. Once state is shared, everyone with bucket access can read that key, so restrict bucket access to people who should have it. I didn't change the key resource because that is a separate decision (for example, moving the upload job to a role).
- **Checkov findings:** checkov passes 27 checks and fails 3 on the bucket: cross-region replication, event notifications, and access logging. I left these as optional hardening rather than adding a second bucket and replication. I suppressed nothing.
- **Bootstrap state:** keep `bootstrap/`'s local state somewhere safe. If you lose it, you'd have to re-import the bucket.
