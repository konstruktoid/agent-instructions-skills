I reproduced this outside Ansible too (bare `apt install auditd && systemctl start auditd` in the same container) — the sandbox's nested container has no working kernel audit netlink interface, so auditd cannot start regardless of capabilities added. This is an environment limitation, not a defect in the role: the original two-restart version would have hit the identical failure on its first restart. I could not get a live pass of `verify.yml`'s new assertions because converge never reaches that point in this sandbox; the assertion logic itself is straightforward slurp+substring checks against content the converge step already writes successfully.
