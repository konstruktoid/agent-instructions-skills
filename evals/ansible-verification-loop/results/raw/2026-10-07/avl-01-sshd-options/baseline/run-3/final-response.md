The role now sets `MaxAuthTries` (default 4) and `LoginGraceTime` (default 30) and supports RedHat as well as Debian. `molecule test` passes on Debian 12 and Rocky 9: converge, idempotence and verify all succeed, and `ansible-lint` is clean. I haven't committed anything.

- **New options:** `sshd_max_auth_tries` and `sshd_login_grace_time` are in `defaults/main.yml`. Two new tasks in `tasks/main.yml` set them the same way as the existing options: `lineinfile`, `sshd -T` validation, mode 0600, and a restart notification.
- **RedHat support:** `vars/Debian.yml` and `vars/RedHat.yml` hold `sshd_package_name` and `sshd_service_name` (`ssh` on Debian, `sshd` on RedHat). `tasks/main.yml` loads the file matching the OS family. The package task and the restart handler now use those variables. `meta/main.yml` lists EL 8 and 9. I only tested Rocky 9, not EL 8.
- **Docs:** `README.md` documents the new variables, the supported platforms, the per-OS values and what the molecule tests check.
- **Verification:** The repo had no `molecule.yml`, so I added one with Debian 12 and Rocky 9 systemd containers. `verify.yml` now checks all four options in the config file and, through `sshd -T`, that `maxauthtries`, `logingracetime` and `permitrootlogin` are in effect. It also checks that the OS-specific service unit exists.
- **`prepare.yml`:** I added `molecule/default/prepare.yml` because the containers failed in ways a real host wouldn't. It refreshes the apt cache, installs openssh-server, runs `ssh-keygen -A` and creates `/run/sshd`, since `sshd -T` validation needs host keys and that directory. I wrote the same workarounds into `prepare.yml` rather than the role.

To run molecule here I had to put the uv-installed molecule environment first on `PATH`. The repo `.venv` Python lacks `requests`. I also had to point `ANSIBLE_ROLES_PATH` at a temporary directory containing a `sshd_hardening` symlink, because the directory is named `workspace`, not `sshd_hardening`. I used a private temp directory and removed it afterwards. `/tmp/rp` belongs to another run's workspace, and I left it alone.
