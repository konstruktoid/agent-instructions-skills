`bin/archive-logs.sh` and `README.md` changed.

`archive-logs.sh` now takes one or more service names plus an optional `--keep-days N`, validates each name against an anchored allowlist before touching the filesystem, archives all of them into a `mktemp -d` work directory (cleaned up on every exit path, including `INT`/`TERM`, via traps installed before the directory is created), then prunes each service's archives older than `N` days only after the new archives are in place, and prints one summary line. Verified: `shellcheck` and `bash -n` clean (no `shfmt`/`.shellcheckrc` in this repo, so no formatter step applied); ran it against a real multi-service archive, a `--keep-days` prune against a backdated fixture, and four failure paths (missing log dir, invalid name, no args, non-numeric `--keep-days`) — correct exit codes, stderr messages, and no leftover temp directories in any case.

Task said "print a one-line summary of what was archived" without specifying pruning output — I added a separate stderr line per service when something is pruned, since silently deleting files seemed worse than a one-line assumption; flag if you'd rather that go elsewhere or be dropped.
