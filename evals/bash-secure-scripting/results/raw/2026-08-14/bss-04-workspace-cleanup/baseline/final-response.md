`bin/clean-workspaces.sh` now takes `--workspace-root` and `--days` (defaulting to the previous `workspaces`/`7`), plus a `--dry-run` flag that lists what would be removed. Along the way I also fixed the unsafe `ls`/unquoted-variable parsing and made removal atomic (`rm -rf "$dir"` instead of clear-contents-then-rmdir, which used to leave dotfiles behind). README updated to match. Verified with a scratch workspace directory: dry-run lists without deleting, real run removes only the stale one, empty workspaces are safely skipped, and bad `--days`/missing root both fail with clear errors.
