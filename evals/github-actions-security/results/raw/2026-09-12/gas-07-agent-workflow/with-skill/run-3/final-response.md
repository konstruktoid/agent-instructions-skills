`.github/workflows/assistant.yml` was rewritten. Before, this was a full repo takeover waiting to happen: `permissions: write-all`, no actor check, `issue_comment` fired on `created` and `edited` from anyone, the comment body was fed straight to the agent as its instructions, the PR head was checked out on a mutable ref, and the agent action itself was unpinned. On a public repo that means any stranger who leaves a PR comment gets an agent with a write-all token to do whatever the comment (or the PR's own files) tells it to.

What changed and why:

- **`permissions: write-all` → `permissions: {}` at workflow level, `contents: write` on the job**, with a comment explaining the scope is for pushing the change. Nothing else was ever needed — write-all also handed the agent scopes like `packages`, `pages`, `actions`, and `administration` it never used.
- **Actor gate added, in two layers, both before checkout.** A job-level `if` restricts the run to `OWNER`/`MEMBER`/`COLLABORATOR` comments on a pull request (`github.event.issue.pull_request != null`) — this alone stops a random forker from spending your model credential. Because `COLLABORATOR` includes read-only invited users, a second step calls `gh api .../collaborators/{user}/permission` and fails the job unless the role is `write` or `admin`. `author_association` is metadata on the comment, not a permission check — don't trust it alone once the job holds a write token and a model API key.
- **Trigger narrowed to `types: [created]`.** `edited` let someone post an innocent comment, then rewrite it after any human glance, to whatever they actually wanted the agent to do.
- **Checkout pinned and resolved properly.** `actions/checkout@v5` (a floating tag) is now pinned to `3d3c42e5aac5ba805825da76410c181273ba90b1` (`v7.0.1`, the current release, resolved via the GitHub API). The `ref` is no longer the mutable `refs/pull/N/head`; it's resolved to a commit SHA fetched at run time, closing most of the window between "comment posted" and "code checked out."
- **Agent config stripped from the untrusted checkout.** A PR from the very person triggering this could ship a `CLAUDE.md`, `AGENTS.md`, or `.mcp.json` that reconfigures the agent's tools or MCP servers before it ever reads the prompt. That step now deletes them.
- **Prompt now marks the comment as data, not instruction**, with explicit begin/end markers. This doesn't neutralize prompt injection — nothing does — but it's the stated separation the containment (actor gate, token scope) actually relies on.
- **`timeout-minutes: 15`** replaces the 360-minute default, and **`concurrency`** is keyed on the issue number so overlapping comments on the same PR serialize instead of racing (not cancelled mid-push, since a cancelled push leaves partial state).

**Left open, and this is a real gap, not a style note:** `acme/coding-agent` doesn't resolve — `gh api repos/acme/coding-agent` returns 404, so there's no commit to pin to. I can't SHA-pin an action that doesn't exist. Confirm the actual action name and version and I'll pin it; until then this workflow still runs an unpinned third-party action, and zizmor correctly flags it as the one remaining high-severity finding (`unpinned-uses`). I also don't know that action's real input schema, so I couldn't add a tool allowlist restricting it to specific commands — check its own docs for that and add it once the SHA is fixed.

Verification: `actionlint` clean. `zizmor --persona=pedantic` clean except the unresolvable `acme/coding-agent` pin above. Both were run offline/without a live workflow run — I did not push a branch or trigger the workflow, since that spends real credentials and is worth a separate go-ahead from you given the actor-gate logic is exactly the part that most needs a live check (e.g., a non-collaborator comment should produce no run at all).

I did not touch `.github/workflows/ci.yml` — out of scope for this request, and it already follows the same conventions (`permissions: {}`, pinned checkout, `persist-credentials: false`, `timeout-minutes`) that I matched here.
