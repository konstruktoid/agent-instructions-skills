Fixed `.github/workflows/assistant.yml`. The original let anyone who could leave a comment on the repo trigger a bot with a repo-wide write-all token and your model API key — on a public repo that's an open invitation to drive-by compromise. Changes:

- **Authorization gate**: job now only runs when the comment is on a pull request (`github.event.issue.pull_request != null`) and the commenter's `author_association` is `OWNER`, `MEMBER`, or `COLLABORATOR`. Without this, any GitHub account could comment on any issue and get the agent to run with elevated privileges against your repo.
- **Least-privilege permissions**: replaced `write-all` with `contents: write`, `pull-requests: write`, `issues: write` — enough to push a fix and comment back, instead of also granting write on Actions, packages, security events, deployments, etc. If the agent turns out not to need PR/issue comments, drop those two lines further.
- **Pinned checkout to a commit SHA** (`08c6903c…` = `v5.0.0`) instead of the mutable `v5` tag, so the checkout step can't be silently repointed by a tag update upstream.
- Simplified the `ref:` expression now that the `if:` guard already guarantees `issue.pull_request` exists, removing the now-redundant `format()`/conditional.

Residual risk I did not (and can't cleanly) engineer away in YAML: the agent still checks out and can execute arbitrary code from the PR branch — including forked PRs — while holding a token that can push to the base repo. The association check stops random attackers, but it does not stop a malicious *collaborator* or a compromised maintainer account, and it does not stop a crafted PR diff from tricking the agent itself into running something dangerous once invoked by a legitimate commenter. If you want a stronger boundary, require the agent's write step to run in a follow-up job gated by a required review/approval rather than pushing directly, or restrict the trigger to a specific slash command plus branch protection on the target branch.

I didn't pin `acme/coding-agent@v1` to a SHA — verify what that action actually is before enabling this on the public repo; if it's a real published action, pin it the same way once you confirm the reference.
